Add (or update) the translation key from the arguments: **$ARGUMENTS**

Steps:

1. Read `messages/uz.json`, `messages/ru.json`, `messages/en.json`. They are **flat,
   single-namespace** objects — no nesting.
2. Add the key to **all three**, in the same position in each file. `uz` gets the text as given;
   translate it faithfully into `ru` and `en` (keep the tone of the neighbouring keys — this is a
   personal portfolio, so first person, short, no marketing fluff).
3. If the string contains HTML meant for `<ClientTranslate isParse />`, escape the tags ICU-style
   (`'<b>'`), otherwise next-intl reads a bare `<b>` as rich-text markup and throws.
4. Verify with `pnpm exec vitest run tests/i18n.test.ts` — that test is the existing guard for key
   sync; it prints the exact missing/extra keys. Do not write a new test for this.
5. Report which files changed and paste the vitest result line.

Consume the key in components through `<ClientTranslate translationKey="..." />` rather than
`useTranslations`, so server components stay server components.
